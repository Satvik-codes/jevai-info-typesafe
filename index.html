typesafe/jev-1.13 — Decision Model

A System One decision model from TypeSafe AI, served via DefAPI. It reads language as a large language model does, but does not generate text. It emits a typed decision, a probability, and a confidence value. Output token consumption is zero.

01 — Overview

Reads, classifies, does not write

Conventional models are optimised to produce text. Jev is optimised to produce a decision that downstream code can act on deterministically.

  • Reads unstructured language. Free text or JSON as state — tickets, logs, plans, transcripts.
  • No generated text. No assistant message, explanation, summary, or code. Output tokens are zero.
  • Classifies rather than generates. Every response is a fixed shape: a probability, a pick, a rating.
  • Self-reported confidence. An explicit value, plus the full distribution across options or levels.
  • Closed type system. Three primitives only. The output form cannot drift between calls.
  • Batched evaluation. A block of typed questions resolves in one request, not one request each.
  • Caller-defined criteria. Branches, options, or scale levels constrain the decision space explicitly.
  • No format engineering. Prompt or schema tuning is not applicable; structure is guaranteed.
02 — Decision primitives

Noul, choice, score

Three question types. Selection depends solely on the shape of the decision. This is the complete query surface of the model.

Noul

Boolean · probability 0–1

A yes/no enquiry returning the probability that the answer is true. Optional criteria describe each branch, anchoring the evaluation to domain conditions.

{
  "deploy_risk": {
    "type": "noul",
    0.55
  }
}

Choice

Single selection · up to 255 options

Options are enumerated with a description each. Returns the selected key, the distribution, and confidence. Intended for triage and routing.

{
  "choice": "payments",
  "probabilities": {
    "payments": .84,
    "frontend": .16 },
  "confidence": .75
}

Score

Ordinal rating · 2–10 ordered levels

Rating against ordered levels. Returns a weighted ordinal value — for example 1.99 on a scale of 0 to 2 — with the legend, distribution, and confidence.

{
  "score": 1.99,
  "probabilities": {
    "2": .99,
    "1": .01 },
  "confidence": .99
}
03 — Request lifecycle

Four stages, no generation stage

State supplied

A plain string, or a JSON object or array of context.

Questions declared

Typed questions with noul, choice, or score and their criteria.

Decision resolved

State evaluated against every question in the request.

Result returned

JSON answers with probability and confidence per question.

05 — Operational notes

Cost behaviour and confidence handling

Cost

With output tokens at zero, cost is a function of input alone. The levers are minimising supplied state and precision of criteria. Batching reduces overhead further.

Confidence

Define a threshold per question type and branch on it. A low-confidence result is a deterministic signal to escalate or defer, not a decision to act upon.

Integration

Clients may be written against a fixed contract and validated without defensive parsing. Distributions permit secondary routing without a second call.
