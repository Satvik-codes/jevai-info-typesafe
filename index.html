Jev 1.13 — TypeSafe AI System One model

Jev is a decision model built and owned by TypeSafe AI, and it is the first model in their System One class. It reads language as a large language model does, but it does not generate text. It emits typed answers with calibrated probabilities and confidence values that software acts on directly. Generation of prose is given up in exchange for structured, type-safe, low-latency decisions.

01 — Overview

Reads, classifies, does not write

The name follows Kahneman's System 1 — fast, single-glance judgement, as distinct from the step-by-step deliberation of a language model. TypeSafe trained Jev with a method they call RLCD (Reinforcement Learning for Calibrated Decisions), tuning its probabilities against real observed outcomes rather than plausibility of phrasing.

  • Reads unstructured language. Free text or JSON as state — tickets, logs, plans, transcripts.
  • No generated text. No assistant message, explanation, summary, or code. String generation is absent by design.
  • Cannot hallucinate structure. Possible outputs and their shape are defined in advance, so type errors are impossible.
  • Calibrated probabilities. Answers carry probabilities tuned against outcomes, not impressions of fluency.
  • Closed type system. Three primitives only. The output form cannot drift between calls.
  • Parallel evaluation. Every question resolves in one round trip against the same state, so adding questions barely moves latency.
  • No sampling knobs. There is no temperature or top_p; generic sampling settings are ignored.
  • Fast by design. TypeSafe reports end-to-end latency in the tens to hundreds of milliseconds, far below comparable LLM decisions.
02 — Decision primitives

Noul, choice, score

Three question types, each sharing type and instructions and each adding its own criteria shape. This is the complete query surface.

Noul

Boolean · probability 0–1 · no criteria

A statement judged for truth, returning a calibrated 0-to-1 probability that it is yes. Optional true/false descriptions are available. Intended for gates and guardrails.

{
  "is_urgent": {
    "type": "noul",
    "instructions": "Is this urgent?" },
  "→ noul": 0.29
}

Choice

Single selection · up to 255 labelled options

Options are supplied as a map of option name to description. Returns the selected key, a probability per option, and a confidence. For routing, triage, and tagging.

{
  "queue": {
    "type": "choice",
    "criteria": { "billing": "…",
                    "bug": "…" } },
  "→ choice": "billing",
  "  confidence": 1.0
}

Score

Ordinal rating · 2–10 ordered level descriptions

Levels are supplied as an ordered array, low to high. Returns a possibly fractional score, a legend echoing the levels, probabilities per level, and a confidence. For severity and lead scoring.

{
  "urgency": {
    "type": "score",
    "criteria": ["routine", "today",
                       "urgent", "critical"] },
  "→ score": 3.0,
  "  confidence": 1.0
}
03 — Access

First-party API, then gateways

Jev is TypeSafe AI's own model. The canonical integration is TypeSafe's own endpoint, using TypeSafe's own SDKs. Aggregators resell access to the same upstream model; they are not the model itself, and their pricing is their own.

  • Request shape is fixed. Three fields: state, questions, and model. An OpenAI-compatible chat client will not work here.
  • Pin the version in production. Aliases move on release. Use jev-1.13.0 once thresholds are tuned against a specific release.

04 — Comparative analysis

Against a standard language model

Comparable reading comprehension, dissimilar output contract.

ConfidenceNot supplied; inferred by the callerCalibrated value plus full distribution

Batch costRises with each additional questionFlat; questions evaluate in parallel
Applicable tasksDrafting, explanation, synthesis, coding, dialogueRouting, triage, scoring, moderation, gating
  • Use an LLM where the output is linguistic: an explanation, a draft, a revision, a reply.
  • Use Jev where the output is a branch: an escalation, a queue, a recorded label, a permission decision.
  • Combine both where classification and prose are both required. A documented pattern is a verified cascade: Jev gates cheaply, the LLM runs only on the accepted path.
05 — Operational notes

Cost, confidence, and known limits

Cost

Output is not billed, so cost is a function of input alone. Levers are trimming state to what the decision needs and precision of criteria. Batching keeps marginal cost per question near zero.

Confidence

Define a threshold per question type and branch on it. A low-confidence result is a deterministic signal to escalate or hand to a fallback model, not a decision to act on.

Limits

Jev is a sampled model. Answers can shift with phrasing, negation, and adversarial content, so it is not replayable for verification. Log model version, latency, and outcome, but avoid logging full state or keys.
